## コミットの前に、差分を減らす側で見直す

対象は、これからコミットする差分（`git diff --cached`。まだステージしていなければ `git diff`）と、同じ作業ブランチで足してきた差分
（`git diff origin/master...HEAD`）。振る舞いは変えない（作り替えだけにする）。見直しで変えたものは、このコミットに含める。

1. **シンプルにし、全体最適にする**: 足したものごとに、同じ判断・同じ値・同じ手順を既に持つ関数・定数・表・部品が無いかを grep で探し、
   あればそれを使って足した側を消す（CLAUDE.md「作業の進め方」の「書く前に、その判断の持ち主を探す」）。使われなくなった引数・既定値・分岐・
   export は同じコミットで消す（.claude/rules/fixing.md「消す・残す」）。読み手が1つの包み・素通しの委譲・使われない fallback は足さない。
2. **要らないテストを消す**: 足した・変えたテストを1本ずつ .claude/rules/testing.md「そのテストは要るか（3問を順に）」に通し、消すと決まったものは消す。
   同じ判断の入力違いは1つのテストの表の行にする。
3. **ライブラリの標準に寄せる**: 自前で書いた処理（地図・日付・入力・HTTP・DB の操作等）ごとに、使っているライブラリ・フレームワークが同じことを
   標準で持たないかを公式の文書で確かめ、持つなら寄せる（CLAUDE.md「作業の進め方」の「使うツール・外部サービス・データ源は、公式を先に読んでから…」）。
   標準で済まず自前で持つなら、その理由を実装の隣に1行書く。
4. **他のファイルの事実をコメントに書かない**: 足した・変えたコメントと docstring が、他のファイル・レイヤーの挙動や持ち物を語っていれば、
   自分の側の契約に書き直すか消す（.claude/rules/comments.md「他所を写さない・代弁しない（docstringも同じ）」の代弁）。差分で消した・変えた事実を
   語っているコメントが差分のファイルに残っていれば、同じコミットで直す。差分で消した・改名した名前は、差分のファイルに限らず
   `python scripts/removed_names.py` でリポジトリ全体（`docs/records/`を除く）の文と置き場の開いた issue から引き（置き場を読むので
   `GH_TOKEN=$FLOW_BOT_TOKEN` を付ける）、今のものとして名指す文は同じコミットで直し、前提に書いた開いた issue へはコメントで知らせる。
   仕組みを消した・置き換えたときは、名前を出さずにその仕組みを語る文（「段の入力が前回と同じなら飛ばす」のような振る舞いの文）も、
   その振る舞いを表す語で grep して探し、同じコミットで直す（名前の網には掛からない）。見つけて報告するだけで終えない。
5. **宣言の事実を、書き写さず・名指さず・外の形のまま持ち込まない**: 足した・変えた文字列と表と分岐ごとに問う。
   - 画面の文（`usage`・説明・ラベル）が、backend の宣言の事実（軸や事実の名前と並び・数え方と並べ方・段の決め方・色の名前）を
     書いていないか。書いていれば、宣言から引くか backend が配る文を出す（docs/architecture/design-principles.md「構造仕様」の
     「費用を述べる文」の当てはめ）。
   - 宣言の鍵の綴り（`group.key === "road"`・`level === "pass"` の類）で1つを選んだり振る舞いを分けたりしていないか。していれば、
     その性質を宣言に持たせて配る。
   - 足した表や関数が、配信元のコード・JSON の形・列名を値へ戻していないか。`domain/` に置いていれば、取りに行く層へ移す
     （docs/architecture/directory-layout.md の `domain/` の行の「読み替えの表も書式で、取りに行く層が持つ」）。

見直しで消した・寄せたあとは、触った範囲のテストと静的検査を回す（.claude/skills/run-checks/SKILL.md「手元の検査の回し方」）。
