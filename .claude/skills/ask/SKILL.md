## 問い

導く原則: 1・2。

ユーザーに求めること（採否・判断・操作のお願い・確認）は、形（`tools/flow-gate/question_template.md`。写して埋める）のとおりにファイルへ書き、
`node .claude/skills/ask/scripts/ask.mjs <番号> <問いのファイル>` で問う（形に合わなければ出さずに合わない所を返すので、直して打ち直す）。ゲートは、最新の
「## 問い」が形に合い答えが無ければ回答待ちにし（完了の条件が全部済めば、採否のほかは問いが残っていても完成にし、問いを出した事実があとで無くなった問いも読まない。docs/conventions/flow.md「ステータスと割り当て」の問い）、形に合わなければ問いとして読まずに合わない所を返す。開発機の対話のセッションで
ユーザーがチャットにいるときは、チャットで聞いて「答え」のとおり記録する。問いを残して終えるときは、回答フォームの直リンク
（`flow.config.json: urls.form` の `/answer?issue=<番号>`）を1件1行で添える。

- **形**（照らすのは `tools/flow-gate/src/questions.js: checkQuestion`）: 判断材料（最初の `<details>`）より前は、1行目の「## 問い（<種類>）」・
  問いの文（1行）・「### 案」と1行1案・空行だけ。判断材料は形の節を、形の順に1つずつ埋める（節の頭は行頭の「**<名前>**:」）。
- **聞くかどうか**: 外から見える振る舞いが変わるときと、目的の読みが割れるときだけ聞く。変わらないなら聞かずに報告して直す。
  答える時点で答えられることだけを聞き、聞いたら答えを待つ。
- **案**: どれにするかを決めてほしいときだけ書く。どう直すか・どう確かめるか（Claude の領分）は案にしない。案の文と当てる作業を一致させる。
  行き先（次のステータス）は書かない（ゲートが答えから決める）。
- 回答フォームは、ユーザーと合意したモックの形で、選ぶ欄1つと書く欄1つを出す（判断は案と「どれでもない（書く欄に書く）」、確かめは項目の一覧と
  「完了にする」のチェック1つ、採否は着手する・保留する・見送る、イレギュラーはやり直す・保留する・見送る。ラベルの欄もある）。判断に要るコメント（保留の理由・確かめる担当の結果）は判断材料に書く。確かめの問いの判断材料は、ゲートが本文の
  条件ごとの「見る所と要点」を写して作るので、確かめてほしい中身はそこへ書く（.claude/skills/file-issue/SKILL.md「ユーザーが確かめる条件」）。問い直すと新しいコメントになり、開いたあとに
  新しい問いが来ていれば送信は断られる。
- **見た目の判断**には、変更前と変更後の画面かモックを添え、画像ごとに画面で見える見出しを付ける。画像は、問いの前に画像だけのコメントを
  1枚ずつ書き（`gh issue comment … --attach '<画像>#<見出し>'`）、そのコメントの添付の URL を判断材料の `![<見出し>](<URL>)` で指す。
  `capture.mjs` で撮ったら、脚本の全文と引数を `<details>` で畳んで同じ issue に書く。
- **製品の言葉で書く**: 実装の語・固有名詞・タスク番号に頼らない。

## 答え

導く原則: 1。

Claude は、タスクの issue のコメントに残った答えだけを判断に使う。

- **チャット**: ユーザーがチャットで決めたことは、Claude がそのやり取り（ユーザーの言葉の引用を含む）を issue にコメントで書き、答えとする。
  ユーザーに回答フォームで打ち直させない。問いに答えた形で残すときは
  `node .claude/skills/ask/scripts/answer.mjs <番号> [--choice <選んだ案か選択肢>] [--done] [--text <ユーザーの言葉の引用を含む文のファイル>]` で書く（下の形になる。
  問いに合わなければ書かずに合わない所を返す）。
- **回答フォーム**: フォームがユーザーの名義で、問いの後ろに次の形で書く。

      ## 回答
      **<問いの文>**

      回答: <選んだ案か選択肢。確かめなら「完了にする」か「完了にしない」。選ばずに書いたなら「どれでもない（書く欄に書く）」>（いつも置く）
      - 確かめた: <完了の条件>（完了にしたとき、項目ごと）
      ラベル: +<付けたもの> −<外したもの>（変えたときだけ）

      <書いた文（書いたときだけ）>

答えは、ユーザーがその項目に答えたものだけ。方針の答えから導いた細部（例外の顔ぶれ・数字・期限）は問いで聞く。答えの範囲を広げても
狭めても読まない（目的に入るものを範囲から外すなら先に問う）。案を並べた問いに、どの案も選んでいない答えが返ったら、読み替えず問い直す。

## 保留と棚卸

導く原則: 1・4。

保留と完了だけは、ユーザーの決定も受ける（`docs/conventions/flow.md`「ステータスと割り当て」）。Claude は自分の判断で保留にしない。

- **保留に入る道**: 問いへの答え「保留」・ステータスの欄を保留にする（担当が持っていれば、ゲートがその実行を取り消す）。ゲートは、ユーザーが
  出すまで保留を保つ。欄で変えるときは理由を求めない。
- **保留を選びうる問いの判断材料**には、保留で何が止まるかと、保留し続けると次に何が起きうるかを書く（「後で判断」の一言で済ませない）。
  置き場はその判断が属するタスクの issue で、判断を待つためだけに issue を作らない。
- **日付で再開するものは保留にしない**: 未着手＋着手可能日時（.claude/skills/file-issue/SKILL.md「ラベルと種類と欄」）で待つ。保留は、人の判断か、
  日付で見に行けない外の出来事を待つものに限る。
- **棚卸**（ステータスの欄）: 未着手にする → Claude の番。完了にする → 完成（完了の条件が残っていれば戻る）。`Close as not planned` → 見送り。
