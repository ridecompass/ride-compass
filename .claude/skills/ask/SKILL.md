## 問い

導く原則: 1・2。

答えを受けるのはゲートで、ゲートは答えのうち次遷移だけを読む。答えで次に動く Claude へは、回答内容（選んだ案とコメント）を漏れなく渡す。
回答フォームは問いの中身から導き、答える人の都合でフォームを増やさない（オープン質問に合わせたフォームは作らない。列挙できる聞きごとは案を立てて判断に、
列挙できないものは、何を書いてほしいかを問いの文に書く）。

ユーザーに求めること（判断・操作のお願い）は、ラベルの形（`tools/flow-gate/question_forms/` のそのラベルのファイル。「## 問い」の行から下を写して埋める）の
とおりにファイルへ書き、`node .claude/skills/ask/scripts/ask.mjs <番号> <問いのファイル>` で問う（形に合わなければ出さずに合わない所を返すので、直して打ち直す）。
ゲートは、最新の「## 問い」がラベルの形に合い、ラベルの出す者が書いたもので、答えが無ければ回答にし（完了の条件が全部済めば、問いが残っていても
完成にし、ゲートが出した問いは同じ事実から同じ問いが出る間だけ読む。docs/conventions/flow.md「ステータスと割り当て」の問い）、外れていれば問いとして読まずに
合わない所を知らせる。開発機の対話のセッションでユーザーがチャットにいるときは、チャットで聞いて「答え」のとおり記録する。問いを残して終えるときは、
回答フォームの直リンク（`flow.config.json: urls.form` の `/answer?issue=<番号>`）を1件1行で添える。

ラベルは、ユーザーが一覧で「何を求められているか」を見分けるためのもので、あわせて問いにどの節を書くかを決める。ゲートはラベルで答えの扱いを変えない。
ラベルごとの決まり（出す者・書く節・判断材料の節）はラベルの形のファイルが持ち、照らしはそこから読む（`tools/flow-gate/src/questions.js: checkQuestion`）。
値の全体が「<…>」の所は書く者が埋め、ほかは決まった値で変えない。ここには、どのラベルにも共通の書き方だけを置く。ラベルを足すときは、形のファイルを1つ足す。

| ラベル | 出す者 | 書く回答内容の節 | 判断材料の節 |
|---|---|---|---|
| 判断 | Claude | 「### 案」（続け方を2つ以上） | 何の話か・利用者への約束・問題が起きる場面・起きない場面・進行中の作業との関係 |
| 操作 | Claude | 「### 済ませること」（何を・どこで・どの手順で） | 何の話か |
| 確かめ | ゲート | 「### 確かめること」（ユーザーが確かめる条件と見る所と要点） | 何の話か |
| 採否・イレギュラー・続行 | ゲート | 書かない | 何の話か（決まった文） |

- **形**: 判断材料（最初の `<details>`）より前は、1行目の「## 問い（<ラベル>）」・問いの文（1行）・（ラベルが書くなら）回答内容の節の見出しと1行1つ・空行だけ。
  行の下に、字下げした属性の行「- <名前>: <値>」を置ける。判断材料はラベルの節を、形の順に1つずつ埋める（節の頭は行頭の「**<名前>**:」）。
  この形で読めること・ラベルの回答内容の節の見出し（無いラベルは書かない）・出す者は、問いを読む前提で、外れるとゲートが読めない理由を知らせ、回答フォームは
  回答内容を出さない。案の決まり・決まった問いの文・判断材料の節は `ask.mjs` が出す前に照らし、ゲートと回答フォームは外れた所を無いものとして読む。
- **案**: 回答内容を手早く伝えるための、書き手が用意した答えの候補（書く欄に同じことを全部打つ手間を省く）。どの案も続け方の違いで、保留・見送りのような
  次遷移は案に書かない（回答フォームのボタンが持つ）。案ごとに行の下へ「- 推奨: <理由>」（ちょうど1つの案）か「- 理由: <出す理由。得るものと失うもの>」を
  1つ書く。2つのラベルにまたがる問い（着手するかとどれで作るか）は、2つの問いに分ける。
- **聞くかどうか**: 外から見える振る舞いが変わるときと、目的の読みが割れるときだけ聞く。変わらないなら聞かずに報告して直す。
  答える時点で答えられることだけを聞き、聞いたら答えを待つ。どう直すか・どう確かめるか（Claude の領分）は案にしない。
- **回答フォーム**は、問いの回答内容の節だけから導く（見た目はユーザーと合意したモック）。エリアは2つで、互いに干渉しない:
  「回答内容」は、案があれば1行ずつの丸（推奨の印と案ごとの理由を添える）、確かめること・済ませることがあれば1行ずつの YES／NO と、
  書く欄（「Claude に伝えること」）。確かめることの YES／NO は本文のユーザーが確かめる約束の値で、初めの値は今の値（チェックがあれば YES）、送ると
  答えと同じ1回の書き込みで本文の約束へユーザーの名義で書く（GitHub で本文のチェックを押すのと同じ）。済ませることは約束ではないので、初めは NO で、
  値は答えに書く。
  「この issue を」は、次遷移のボタンの横並び（続ける・保留する・見送る）で、1つを必ず選ぶ。完了は次遷移に無く、約束が全部果たされたらゲートが事実から
  決める。推奨も次遷移も最初から選んだ状態にしない。ラベルの欄もある（ゲートが付ける「問い: <ラベル>」は出さない）。判断に要るコメント（保留の理由・検証担当の結果）は
  判断材料に書く。確かめの問いは、ゲートがユーザーが確かめる条件と、条件ごとの「見る所と要点」を確かめることに並べるので、確かめてほしい中身は
  そこへ書く（.claude/skills/file-issue/SKILL.md「ユーザーが確かめる条件」）。問い直すと新しいコメントになり、開いたあとに新しい問いが来ていれば送信は断られる。
- **見た目の判断**には、変更前と変更後の画面かモックを添え、画像ごとに画面で見える見出しを付ける。画像は、問いの前に画像だけのコメントを
  1枚ずつ書き（`gh issue comment … --attach '<画像>#<見出し>'`）、そのコメントの添付の URL を判断材料の `![<見出し>](<URL>)` で指す。
  `capture.mjs` で撮ったら、脚本の全文と引数を `<details>` で畳んで同じ issue に書く。
- **製品の言葉で書く**: 実装の語・固有名詞・タスク番号に頼らない。

## 答え

導く原則: 1。

Claude は、タスクの issue のコメントに残った答えだけを判断に使う。

- **チャット**: ユーザーがチャットで決めたことは、Claude がそのやり取り（ユーザーの言葉の引用を含む）を issue にコメントで書き、答えとする。
  ユーザーに回答フォームで打ち直させない。答えを待つ問いがある issue では（ゲートは答えの次遷移でしか問いを閉じないので、自由な文の
  コメントでは問いが残る）
  `node .claude/skills/ask/scripts/answer.mjs <番号> --next <続ける|保留|見送り> [--plan <選んだ案>] [--yes <行>]... [--text <ユーザーの言葉の引用を含む文のファイル>]` で書く
  （下の形になる。問いに合わなければ書かずに合わない所を返す）。
- **回答フォーム**: フォームがユーザーの名義で、問いの後ろに次の形で書く。3つの欄（次遷移・選んだ案・コメント）は、空でも省かない。

      ## 回答
      **<問いの文>**

      次遷移: <続ける・保留・見送りのどれか>
      選んだ案: <選んだ案。選ばなければ「選ばなかった」、問いに案が無ければ「なし（問いに案が無い）」>
      済ませること:（済ませることのある問いだけ）
      - YES: <済ませた行>
      - NO: <済ませていない行>
      ラベル: +<付けたもの> −<外したもの>（変えたときだけ）
      コメント:
      <書いた文。書かなければ「コメント: なし」の1行>

ゲートが読むのは「次遷移:」の行だけで、回答内容（選んだ案・済ませることの値・コメント）は遷移先が読む（確かめることの値は本文の約束にある）。答えは、ユーザーがその項目に答えたものだけ。方針の答えから導いた細部
（例外の顔ぶれ・数字・期限）は問いで聞く。答えの範囲を広げても狭めても読まない（目的に入るものを範囲から外すなら先に問う）。

## 保留と棚卸

導く原則: 1・4。

保留と完了だけは、ユーザーの決定も受ける（`docs/conventions/flow.md`「ステータスと割り当て」）。Claude は自分の判断で保留にしない。

- **保留に入る道**: 問いへの答え「保留」・ステータスの欄を保留にする（担当が持っていれば、ゲートがその実行を取り消す）。ゲートは、ユーザーが
  出すまで保留を保つ。欄で変えるときは理由を求めない。
- **保留を選びうる問いの判断材料**には、保留で何が止まるかと、保留し続けると次に何が起きうるかを書く（「後で判断」の一言で済ませない）。
  置き場はその判断が属するタスクの issue で、判断を待つためだけに issue を作らない。
- **日付で再開するものは保留にしない**: 着手可能日時（.claude/skills/file-issue/SKILL.md「ラベルと種類と欄」）で待つ（ステータスは待機）。保留は、人の判断か、
  日付で見に行けない外の出来事を待つものに限る。
- **棚卸**（ステータスの欄）: 保留から出す（保留でない値にする） → ゲートが事実から決め直す。完了へ動かす → 完成（完了の条件が残っていれば戻る）。`Close as not planned` → 見送り。
